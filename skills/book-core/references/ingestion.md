# 取り込み手順

ユーザーがKindleのハイライト（read.amazon.co.jp/notebook からのコピー等）や読書メモを貼ったときの手順。

## 1. 本と分野を特定する

- 書名が分かれば、SKILL.md の「Skill一覧と振り分け」の番号から担当Skillを決め、そのSkillの `references/index.md` で slug とモジュールを確認する。
- 5分野のどれにも入らない本は、無理に入れない。近い分野があればそこに入れ、なければ新しい分野が必要かユーザーに相談する。

## 2. ハイライトを読み解く

- Kindleのコピーは「黄色のハイライト | 位置: 123」のような行と本文が交互に並ぶ。位置番号は引用元として残す。
- ハイライトから読み取れることと、Claudeの背景知識で補うことを分ける。補った箇所には「（補足）」と付ける。後で見たとき、本に書いてあったことと混ざらないようにするため。

## 3. 本のノートを書く

`assets/book-note-template.md` に沿って、担当Skillの `references/books/<slug>.md` を書く。

- あらすじではなく「判断ルール」（〜なら〜する）の形にする。相談にそのまま使えるようにするため。
- 主張ごとに根拠レベル（A〜D）を付ける。
- 引用は短く（1つ数行まで）。長い本文の書き写しは避け、自分の言葉でまとめる。著作権への配慮と、ノートを判断用に保つため。
- 「自分メモ」はユーザーにしか書けない。空なら1〜2問だけ聞く（実践してどうだったか、どこが刺さったか）。答えがなければ空欄のまま残す。

## 4. 統合する

ここが一番大事な工程。本を読むほど知識が「本の寄せ集め」ではなく「分野の専門知識」になるのは、この統合による。

1. **分野のモジュール**（担当Skillの `references/modules/`）の「統合した判断ルール」を更新する。
   - ほかの本と同じ原則なら、既存のルールに書名を足して根拠を厚くする（新しい行を増やさない）
   - 新しい原則なら追加する
   - ほかの本と違う主張なら「論点」に両方の立場と使い分けを書く
2. その原則が**ほかの分野でも使える**なら、`references/principles/` の共通原則に書き、分野のモジュールには1行リンクだけ残す。すでに共通原則にあるなら、そこに分野での現れ方と書名を足す。
3. 分野の組み合わせで新しい典型相談が見つかったら `references/crosslinks.md` に足す。

## 5. 一覧を更新する

担当Skillの `references/index.md` で、その本の状態を「作成済」にし、根拠レベルを埋める。

## 6. 保存する

- Skillのフォルダに書き込める環境（Claude Code でリポジトリ管理している場合など）なら、直接ファイルを更新する。
- 書き込めない環境（claude.ai にインストールしたSkill）では、更新したファイルの全文を出力し、どのSkillのどのファイルを置き換えるかを一覧にする。

最後に、更新したファイルと、統合で変わった判断ルールを短く報告する。
