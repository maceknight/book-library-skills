# 読書ライブラリ 共通基盤

ユーザーが読んだ本を、Claudeが相談に使える知識として蓄える仕組みの中心。
分類は本棚の整理のためではなく、**相談を見たときにどのSkillを使えばよいかを判断しやすくするため**にある。

このスキルの役割は4つ。

1. 相談をどのSkillに振り分けるか決める
2. 全Skillに共通する相談ルールと根拠レベルを持つ
3. 分野をまたぐ共通原則を一箇所で持つ（`references/principles/`）
4. 本を取り込む手順を持つ（`references/ingestion.md`）

---

## 知識の3層

| 層 | 置き場所 | 中身 |
|---|---|---|
| 本のノート | 各分野Skillの `references/books/` | 1冊ごとの主張・判断ルール・根拠。取り込みの一次資料 |
| 分野のモジュール | 各分野Skillの `references/modules/` | 同じ分野の複数の本を統合した判断ルールと論点 |
| 共通原則 | このスキルの `references/principles/` | 2つ以上の分野で使う原則 |

**どこに書くかの決まり**：同じルールを複数の場所にコピーしないため。

- 1冊の本だけの主張 → その本のノート
- その分野の中だけで使う原則 → その分野のモジュール
- 2つ以上の分野で使う原則 → 共通原則。分野のモジュールには「→ book-core 共通原則：〇〇」と1行リンクだけ書く

相談に答えるときは、モジュール（統合済みの判断ルール）を先に読み、根拠を示したいときや詳細が必要なときに本のノートを読む。

### 主担当の決め方

1. **相談者が変えたいもの**の分野を主担当にする。
   原因が別の分野にあっても、目的の分野が主担当。
   例：「貯金が続かない」→ 変えたいのは貯金額なので book-money が主担当。原因の説明に book-psychology（現在バイアス）や共通原則（仕組み化）を使う。
2. 補助のSkillは最大2つまで。全部のSkillを並べると答えがぼやける。
3. よくある組み合わせは `references/crosslinks.md` にまとめてある。

## 相談の共通ルール（全Skill共通）

- **ノートがない本の内容を作らない。** 各Skillの `index.md` で状態が「作成済」の本だけを根拠にする。一般知識で補うときは「一般的には」と明示する。ユーザーは蔵書由来の知識だと信じて判断するため。
- **根拠レベルを伝える。** 体験談と研究で支持された原則を同じ口調で話さない。
- **本同士の対立を隠さない。** 違う主張があれば両方と、どんな人・状況ならどちらが向くかを示す。
- **当てはまらない条件を添える。**
- **状況が分からないと答えが大きく変わるときは、先に1〜2点だけ聞く。**
- **形式は相談の重さに合わせる。** 雑談的な質問に見出しや表は要らない。

各分野に固有の注意（お金の制度の鮮度、メンタルの安全など）は各SkillのSKILL.mdにある。

## 根拠レベル

| レベル | 意味 |
|---|---|
| A | 学術研究や長期データで広く支持されている |
| B | 実務家の間で広く支持され、データも一部ある |
| C | 著者の経験や事例が中心で、再現性は検証されていない |
| D | 検証が難しい、反対のデータがある、または利益相反が強い |

1冊の本でも主張ごとにレベルは違う。本全体の目安と主張ごとのレベルの両方を記録する。

## 共通原則

分野をまたいで使う原則。各ファイルに、原則の要旨・分野ごとの現れ方・関連する本・注意点をまとめる。

| ファイル | 原則 | 主に関わるSkill |
|---|---|---|
| `principles/shikumi.md` | 仕組み化：意志の力に頼らない | money、work、life、time-habit |
| `principles/erabu.md` | 選ぶ・減らす：やらないこと、買わないことを決める | time-habit、money、work |
| `principles/kettei.md` | 意思決定：判断の型とバイアス | work、money、psychology |
| `principles/shoki.md` | 行動の初速：小さく始め、早く失敗する | time-habit、work、life |
| `principles/suchi.md` | 数値化：測れるものにして管理する | work、money、time-habit |
| `principles/yugen.md` | 有限性：時間・お金・気力には限りがある | time-habit、money、life |

原則が増えたら、この表とファイルを追加する。2つ以上の分野で使われない原則は、共通原則にしない。

## 取り込み

Kindleのハイライトや読書メモを取り込む手順は `references/ingestion.md`。ノートのひな形は `assets/book-note-template.md`。

## サブSkillへの分け方

各分野Skillは、中を「モジュール」に分けた1つのSkillとして始める。
次の条件がそろったら、モジュールを独立したSkillに分ける。

1. そのモジュールへの相談の入口（ユーザーが使う言葉や状況）が、ほかのモジュールとほとんど重ならない
2. ノートが増え、Skillを使うたびに読む量が負担になっている
3. 実際に、Skillの選び間違いや使い漏れが起きている

逆に、相談がモジュールをまたいで混ざりやすいうちは分けない。分けるとClaudeがSkillを選びにくくなるため。
